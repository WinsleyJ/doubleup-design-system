# ADR-004: Common-laag op NL Design System `basis`-tokens

- **Status:** geaccepteerd (met voorwaarden, zie Gevolgen)
- **Datum:** 2026-10-31
- **Beslissers:** Winsley (voorwaardelijk besluit), Claude (toets)

## Context

Winsley wil de common-laag afstemmen op de NL DS `basis`-tokens, **mits** dat ook werkt voor niet-overheidsprojecten en alle beoogde platforms. Dit ADR legt de toets vast.

## Besluit

**Ja: de common-laag gebruikt `basis`-tokens** als contract; ontbrekende zaken vullen we aan onder `dup` (bv. `dup.motion.*`, `dup.opacity.*`, `dup.z-index.*`, eventuele typografie-rollen voor display-koppen).

## Gevolgen / voorwaarden

1. **Versie vastpinnen** (nu 3.1.1). Upgrades alleen bewust, met changelog-check; `check-contract` (stap 2) vergelijkt onze common-laag met de gepinde definitie.
2. **Licentie:** we kopiëren hun bestanden niet in onze repo; we gebruiken hun package hooguit als devDependency om namen te valideren, en schrijven onze eigen waarden. Of het overnemen van alleen tokennamen onder EUPL valt, is een juridische vraag — Claude is geen jurist; bij twijfel even laten checken voordat er klantwerk op gebouwd wordt.
3. **Uitstapstrategie:** omdat componenten/adapters via `dup`-componenttokens lopen, raakt een eventueel vertrek bij `basis` alleen de common-laag.
4. Bijkomend voordeel: NL DS Candidate-componenten en de NL DS theme-wizard kunnen onze thema's direct gebruiken.
